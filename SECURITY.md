# Security policy

## Supported versions

Security fixes go to the latest release of each module (`errors`, `log`,
`log/otel`, `helpers`, `api`). Older lines get fixes only when the latest
release would force a breaking upgrade.

## Reporting a vulnerability

Please do not open a public issue. Report it privately through
**GitHub → the affected repository → Security → Report a vulnerability**.
Include the module and version, what an attacker can do, and a minimal
reproduction if you have one.

You should get an answer within a week. After a fix is released, a GitHub
security advisory names the fixed version.
